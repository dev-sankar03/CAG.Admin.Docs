# 02 — Rider Management: Company & Client Status Separation (Milestone 1)

> wizard, Client Details.

## 1. Requirement (as specified)

1. **Separate Company Status and Client Status** into two columns.
   - **Company Status** keeps all current options **except** remove `Free ID`, **add** `Legal Issue`.
   - **Client Status** is a new drop-down under *Employment Information* on the Client Details page;
     saved and displayed there.
2. **Client Status maps to the Client ID** (not the Rider). Both Company Status and Client Status
   shown in the **Client User ID** module.
3. **Client Status list:** Active, Client Suspended, Churn, Clearance Completed, Free ID,
   ID Issued for Part-Time. (A later section adds **Vacation** and **Working Part-Time / Part-Time
   Ready** — reconcile the canonical list.)
4. **Status automation:**
   - If a client is set to **Vacation**, Company Status auto-updates to Vacation; on return, Company
     Status reverts to the previous status.
   - If marked **Part-Time**, the rider flows into the Part-Time module ([07](07-part-time-free-id-management.md)).
5. **Onboarding update:**
   - Keep existing Vehicle Type, Visa Process, Location Transfer, Employment Type options.
   - **Add "Order Type"** dropdown (same values as the Order module) — see [06](06-order-values.md).
   - Unchanged through the License Process.
   - **Add Client Status** dropdown at the **Arara Pending** stage; updated manually from the
     approved list; auto-reflects into Client Details.
   - **Edit option** in Client Details to update Client Status anytime.

## 2. Impact & Changes

### UI (`CAG.Admin.UI`)
- **Rider grid** (`(pages)/Rider/index.tsx`, `constants/grid-props/rider.tsx`) — the single Status
  column becomes **two** columns: Company Status + Client Status.
- **Client Details / Client User ID module** — new Client Status dropdown under Employment
  Information, saved + displayed; edit option.
- **Onboarding wizard** (`components/modals/rider/*`) — add Order Type step/field
  ([06](06-order-values.md)) and a Client Status field at the Arara Pending stage.
- Status filters on the grid split into two filter sets.

### API / DB (`CAG.Admin.API`)
- **Company Status enum change** — remove `FreeId`, add `LegalIssue` to `RiderStatuses`
  (`Domain/Enums/RiderStatuses.cs`) / `RiderStatus` table.
  - ⚠️ **`FreeId (4)` is load-bearing today.** It is (a) an exit status that auto-unassigns the
    vehicle in `RiderService.ChangeRiderStatus` / `UpdateRiderAsync`, and (b) generated by
    onboarding for Part-Time riders (`AddRiderModal` sets `RiderStatus.FREE_ID`). Removing it from
    *Company* status means "Free ID" moves to *Client* status — every current use of the enum value
    must be re-pointed. This is the riskiest single change in Phase II.
- **New Client Status concept** — there is **no client-status field today**. Options:
  - add a `ClientStatus` column on `ClientUserId` (the requirement says "map to Client ID"), backed
    by a `ClientStatus` lookup/enum;
  - expose it through the Client User ID + Client Details endpoints.
- **Status automation service** — Client→Company status sync (Vacation both ways, Part-Time routing).
  Needs a single service method so the rule lives in one place, not scattered.
- **Onboarding** — persist Order Type ([06](06-order-values.md)) and Client Status (Arara Pending).

### Cross-cutting
- This requirement **redefines status** platform-wide; sequence it **before** [01](01-main-dashboard.md)
  (rider-count cards), [03](03-rider-performance-page.md) (shows both statuses), and
  [07](07-part-time-free-id-management.md) (Free ID lives in client status).
- ⚠️ The vehicle auto-unassign on `FreeId` must be reconsidered alongside
  [14 #3](14-misc-changes.md) (stop auto-unassign on Vacation) and
  [rider-vehicle-assignment](../rider-management.md).

## 3. Open Questions & Suggestions

### UI-side
- **Q:** Two status columns on an already-wide rider grid — keep both always visible, or one default
  + one toggle via the column menu?
  💡 Both visible by default (they're core); the grid's Columns menu already lets users hide either.
- **Q:** Client Status dropdown — free per-rider, or constrained by Company Status (e.g. can't be
  "Working Part-Time" if company status is Terminated)?
  💡 Constrain with a validation map; show only valid client statuses for the current company status.
  Provide the matrix (see Business Q below).
- **Q:** Where exactly is "Arara Pending" in the current onboarding wizard steps
  (`basic-info` / `documents-info` / `surety-person` / `review`)? It isn't a current step name.
  💡 Confirm with client — likely an HR Workflow task stage, not a wizard step. If so, the Client
  Status field belongs in the HR Workflow task UI, not `add-rider-modal`.

### API / Data-side
- **Q:** Does Client Status attach to `ClientUserId` (the doc says "map to Client ID") or to
  `ClientRiderConfig` (the rider↔client mapping)? These differ when a client id is reused across
  riders (Part-Time).
  💡 Attach to **`ClientUserId`** as the requirement states, so "ID Issued for Part-Time" is a
  property of the ID, not the current holder — this is exactly what [07](07-part-time-free-id-management.md)
  needs. `ClientRiderConfig` still records who holds it when.
- **Q:** Reconcile the **three overlapping status lists** in the doc (Rider Management section vs
  Dashboard section vs Part-Time section). Which is canonical?
  💡 Adopt the Part-Time section's superset as canonical: **Active, Client Suspended, Churn,
  Clearance Completed, Free ID, ID Issued for Part-Time, Vacation** (+ "Working"/"Ready to Work" as
  Part-Time *rider* states, tracked separately — not client statuses). Document one enum.
- **Q:** Removing `FreeId` from company status — migrate existing `FreeId` company-status rows to
  what? (`LegalIssue`? `Active`? Client-status `Free ID`?)
  💡 Data migration: existing company `FreeId` riders → set company status to `Active` (or a new
  neutral) **and** set the client's status to `Free ID`. Needs a one-time script + client sign-off on
  the target value.
- **Q:** The Vacation-sync rule "revert to previous status" — where is the previous status stored?
  Nothing tracks status history today.
  💡 Add a `PreviousStatusId` column (or a small status-history table) so the revert is deterministic;
  a history table also serves audit needs elsewhere ([09](09-vacation-management.md)).
- **Q:** Company Status auto-update from Client Status — is this a synchronous write on client-status
  change, or a batch/derived value?
  💡 Synchronous, inside the client-status update transaction, via the single sync service method;
  avoid the GET-side-effect pattern that already causes trouble
  ([known-behaviours](../known-behaviours.md)).

### Business / Product
- **Q:** Provide the **full Company-Status × Client-Status validity matrix** — which combinations are
  legal, and which client statuses force which company statuses.
  💡 Client to draft; we implement as a config map. Minimum: Vacation↔Vacation, Free ID + Part-Time
  routing, ID Issued for Part-Time.
- **Q:** "Legal Issue" (new company status) — does it restrict anything (payroll, assignment) or is
  it informational?
  💡 Confirm; suggest treating it like Suspended for assignment purposes unless told otherwise.
